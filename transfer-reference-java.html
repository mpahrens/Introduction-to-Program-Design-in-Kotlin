01 / Files, running & debugging

Keep IntelliJ. Add a Java class.

A JDK supplies the compiler and runtime. This guide uses Java 21–24 with no preview features.

A complete starting file

Kotlin
fun main() {
    val name = "Gompei"
    println("Hello, $name!")
}
Java
public class Hello {
    public static void main(String[] args) {
        final String name = "Gompei";
        System.out.println("Hello, " + name + "!");
    }
}

Save the Java program as Hello.java: the public class and filename must agree. Braces group statements; most statements end with a semicolon. public makes the entry point accessible, static means it needs no object, and void means it returns no result. args holds command-line arguments.

Library calls and imports

Kotlin
import kotlin.math.sqrt

fun main() {
    println(sqrt(81.0)) // 9.0
}
Java
public class Roots {
    public static void main(String[] args) {
        System.out.println(Math.sqrt(81.0));
    }
}
  1. Create: make a Java project in IntelliJ IDEA, select a JDK from 21 through 24, and add a Java class. Match the project language level to that JDK.
  2. Run in IntelliJ: just as with Kotlin, click the gutter arrow beside main and choose Run. The IDE compiles and runs the program; read its output in the Run window.
  3. Debug in IntelliJ: use the same workflow as Kotlin: click the gutter to set a breakpoint, then choose Debug instead of Run. Inspect variables, Step Over a line, Step Into a call, and Resume.
  4. Read errors: fix compiler errors before running. For a runtime exception, read its type and message, then locate your first relevant source line in the stack trace.

Optional terminal workflow: run javac Hello.java, then java Hello from the same directory. These commands compile and run separately; IntelliJ handles those steps when you use Run or Debug.

Snippet convention: unless a complete class is shown, put Java methods and nested type declarations inside class Demo { … }, and executable statements inside its public static void main(String[] args). Put imports before the class; a comment such as // import java.util.List; names an import to add there without the comment markers. Examples are independent except where reuse is stated. Math and String need no import; types such as List do.

02 / Names, assignment & scope

Put the type before the name.

Java checks types at compile time. Local type inference does not make a variable dynamically typed.

Fixed bindings and reassignment

Kotlin
val limit: Int = 3
var count: Int = 0
count += 1
val label = "ready"
Java
final int limit = 3;
int count = 0;
count += 1;
var label = "ready"; // inferred String
// label = 7; // compile error

final prevents a variable from being reassigned, like a Kotlin val. After final int limit = 3;, you cannot assign limit = 4;. A Java local var infers a fixed type but permits reassignment, unlike Kotlin val. Use final var to infer the type while preventing reassignment. Java var needs an initializer and cannot replace a method parameter or return type.

What does static mean?

static means a member belongs to the class, rather than to each object. Call Math.sqrt(81.0) without creating a Math object. A static field is shared by the class instead of having a separate value for each object. final answers whether a variable can be reassigned; static answers whether a member belongs to the class or to an object. Sheet 6 explains when to choose a static method.

Blocks and parameters have local names

Kotlin
fun nextCount(count: Int): Int {
    val next = count + 1
    return next
}
val ready = true
if (ready) {
    val message = "go"
    println(message)
}
// message is out of scope.
Java
static int nextCount(int count) {
    int next = count + 1;
    return next;
}
// In main:
boolean ready = true;
if (ready) {
    String message = "go";
    System.out.println(message);
}
// message is out of scope.

Parameters and local declarations belong to their method or block. Local variables must be assigned before use: int total; does not give a local variable a usable zero value. Fields and array elements do receive default values, but explicit initialization often communicates intent better.

final does not freeze an object. final prevents a variable from being reassigned. If it holds a mutable list, you can still add or remove elements; you just cannot assign a different list to that variable. See sheet 11.

03 / Numbers & Booleans

Recognize primitives and their boxed forms.

Kotlin Int, Double, and Boolean usually become Java int, double, and boolean in simple calculations.

Arithmetic and conversion

Kotlin
val whole = 7 / 2          // 3
val decimal = 7.0 / 2      // 3.5
val remainder = -7 % 2     // -1
val converted = 7.toDouble()
val parsed = "42".toInt()
val text = 42.toString()
Java
int whole = 7 / 2;         // 3
double decimal = 7.0 / 2;   // 3.5
int remainder = -7 % 2;    // -1
double converted = (double) 7;
int parsed = Integer.parseInt("42");
String text = Integer.toString(42);

Both languages truncate integer division toward zero. Converting after division cannot recover a fraction: (double) (7 / 2) is 3.0. Convert an operand first. Java allows widening conversions such as int to double; narrowing usually needs a cast. Invalid integer text throws NumberFormatException.

Comparisons and short-circuit logic

Kotlin
val age = 20
val enrolled = true
val eligible = age >= 18 && enrolled
val needsHelp = !enrolled || age < 18
val squareRoot = kotlin.math.sqrt(81.0)
Java
int age = 20;
boolean enrolled = true;
boolean eligible = age >= 18 && enrolled;
boolean needsHelp = !enrolled || age < 18;
double squareRoot = Math.sqrt(81.0);

Why are there two forms of each primitive type?

Java separates simple values from objects. A primitive such as int stores an integer value directly and cannot be null. Its wrapper class, Integer, represents an integer as an object. Each primitive has a wrapper; the same distinction applies to the other pairs below.

Primitives support calculations without requiring a wrapper object. Wrappers let values participate in APIs that expect objects, including generic collections: List<Integer> is valid, but List<int> is not. A wrapper variable can also hold null for a missing value. Prefer primitives for ordinary calculations; use wrappers when an API or missing-value convention requires them.

KotlinJava primitiveJava wrapper / generic argument
BytebyteByte
ShortshortShort
FloatfloatFloat
IntintInteger
LonglongLong
DoubledoubleDouble
BooleanbooleanBoolean
CharcharCharacter

Numbers have limits. Java int is a signed 32-bit integer; overflow wraps. double uses binary floating point, so use a tolerance for calculated decimal results. Java often converts automatically: Integer boxed = 7; boxes an int, and int n = boxed; unboxes it. Unboxing null throws NullPointerException. Compare wrapper contents with equals, not reference ==.

04 / Strings & missing values

Use equals for object contents.

Java has no Kotlin-style nullable type suffix or safe-call operator. A String reference may hold null.

Read, compare, and build text

Kotlin
val name = "Gompei"
val first = name[0]           // 'G'
val size = name.length       // 6
val greeting = "Hi, $name"
val same = name == "Gompei"
val part = name.substring(0, 3) // "Gom"
Java
String name = "Gompei";
char first = name.charAt(0);  // 'G'
int size = name.length();     // 6
String greeting = "Hi, " + name;
boolean same = name.equals("Gompei");
String part = name.substring(0, 3);

Strings are immutable in both languages. Indices start at zero and the substring end is excluded. Java == compares object identity for references, not string contents. Use equals for contents; Objects.equals(a, b) also handles null. For primitive numbers and enum constants, == is appropriate.

Handle a missing value explicitly

Kotlin
val nickname: String? = null
val length = nickname?.length ?: 0
val display = nickname ?: "guest"
println(display) // guest
Java
String nickname = null;
int length = nickname == null
    ? 0 : nickname.length();
String display = nickname == null
    ? "guest" : nickname;
System.out.println(display); // guest

The conditional operator condition ? yes : no chooses one value. Check for null before calling an instance method. nickname.length() would throw NullPointerException here. Java reference types do not enforce the non-null promise that ordinary Kotlin types provide.

Optional is another return convention. A search can return Optional<String> instead of a possibly-null string. Use orElse("guest") to supply a fallback. An empty Optional differs from an empty string. Follow the API’s stated convention; see the search example on sheet 10.

Official references: StringObjectsOptional

05 / if, when & named choices

Use if for actions, ?: or switch for values.

Much everyday Java code uses statements and variable updates, unlike the expression-oriented style we have practiced in Kotlin.

An expression produces a value; a statement directs an action. In Kotlin we often assign the result of an entire if or when. Java commonly declares a variable and assigns or updates it inside a branch. Java if itself produces no value; ?: and modern switch expressions offer value-producing alternatives.

A common statement-oriented translation

Kotlin
val age = 21
val label = if (age > 21) {
    "adult"
} else {
    "youth"
}
Java
int age = 21;
String label;
if (age > 21) {
    label = "adult";
} else {
    label = "youth";
}
System.out.println(label); // youth

Both branches assign label, so it is safe to use afterward. This example assigns it once on either path; longer Java procedures often reassign variables as they work. That is common style, not a requirement to make everything mutable. Use final when reassignment is unnecessary, and expressions when they make the result clearer.

Two choices and a named set of choices

Kotlin
val age = 21
val label = if (age > 21) "adult" else "youth"

enum class Season { SPRING, SUMMER, FALL, WINTER }
fun clothing(s: Season): String = when (s) {
    Season.SUMMER -> "shorts"
    Season.WINTER -> "coat"
    Season.SPRING, Season.FALL -> "jacket"
}
Java
// In main:
int age = 21;
String label = age > 21 ? "adult" : "youth";

// Inside Demo, outside main:
enum Season { SPRING, SUMMER, FALL, WINTER }
static String clothing(Season s) {
    return switch (s) {
        case SUMMER -> "shorts";
        case WINTER -> "coat";
        case SPRING, FALL -> "jacket";
    };
}

Each arrow chooses one branch without falling through. The semicolon after the closing brace ends the return statement. Covering every enum constant makes this switch exhaustive without a default. A block branch uses yield to supply its value. Pass a non-null season.

Ordered conditions

Kotlin
fun signLabel(n: Int): String = when {
    n < 0 -> "negative"
    n == 0 -> "zero"
    else -> "positive"
}
Java
static String signLabel(int n) {
    if (n < 0) {
        return "negative";
    } else if (n == 0) {
        return "zero";
    } else {
        return "positive";
    }
}

Keep the same case analysis. A Kotlin when with arbitrary Boolean conditions often becomes an if / else if / else chain. Do not force every condition into a switch. Pattern switches over sealed data appear on sheet 8.

Official references: Switch expressions

06 / Function design & testing

A static method can play the role of a function.

Keep the purpose, signature, stub, examples, inventory, implementation, and debugging steps.

Purpose, signature, and implementation

Kotlin
/** Computes a package's shipping cost. */
fun shippingCost(weight: Double,
                 express: Boolean): Double {
    val base = if (weight <= 1.0) 5.0
        else 5.0 + (weight - 1.0) * 1.5
    return base + if (express) 6.0 else 0.0
}
Java
/** Computes a package's shipping cost. */
static double shippingCost(double weight,
                           boolean express) {
    double base = weight <= 1.0 ? 5.0
        : 5.0 + (weight - 1.0) * 1.5;
    return base + (express ? 6.0 : 0.0);
}

Java puts the return type before the method name and each parameter type before its name. A stub could return 0.0 until the calculation is ready. Methods returning no result use void. Java has no named arguments or default parameter values: pass every argument in order, or define an overload that delegates to another method.

Deciding whether a method should be static

An instance call such as player.awardPoint() implicitly supplies player as this. Its fields are available without being listed as parameters. Use static only when an operation needs no such implicit object state. In idiomatic object-oriented Java, use static sparingly; many classes need no static methods. Independent utilities remain a useful exception.

  1. Does it read or change this object’s fields? Use an instance method, without static: player.awardPoint() updates that player’s points.
  2. Does it implement an interface operation or behavior that varies by object? Use an instance method, even if it currently needs no fields. See sheet 8.
  3. Is it an independent calculation with explicit inputs? A static utility can fit, as with shippingCost(weight, express).
  4. Are you adding static just so main can call it? Create the appropriate object in main and call its instance method instead.

static does not guarantee purity. Java permits static methods to use shared fields or mutate explicit arguments. Avoid hiding utility inputs in shared state. These examples preserve the course’s function-based style; do not make every method static.

Examples that run as tests

These tests reuse shippingCost above.

Kotlin
// Course assertion library:
assertSoftly {
    shippingCost(2.0, false) shouldBe
        (6.5 plusOrMinus 0.01)
    shippingCost(2.0, true) shouldBe
        (12.5 plusOrMinus 0.01)
}
Java
// In main; standard Java assertions:
assert Math.abs(shippingCost(2.0, false)
    - 6.5) <= 0.01 : "standard shipping";
assert Math.abs(shippingCost(2.0, true)
    - 12.5) <= 0.01 : "express shipping";

Enable Java assertions: run java -ea Demo, or add -ea to the run configuration’s VM options. Otherwise these assertions are skipped. A failed assertion throws AssertionError and stops this run at the first failure; it does not collect failures like assertSoftly. Passing assertions print nothing.

A helper method and a call

Kotlin
fun doublePoints(points: Int): Int {
    return points * 2
}
println(doublePoints(6)) // 12
Java
static int doublePoints(int points) {
    return points * 2;
}
// In main:
System.out.println(doublePoints(6)); // 12

Test behavior, not the stub. Keep the expected results while replacing default values. Cover boundaries and alternative branches. Java has no standard TODO() expression; throwing an exception for unfinished code interrupts execution. Assertions are for checking assumptions and tests, not for required input validation.

07 / Compound data & copies

Use a record for a fixed group of values.

A Java record is a compact data carrier with a constructor, accessors, and generated equality.

Define, construct, and select

Kotlin
data class Book(val title: String,
                val pages: Int)
val book = Book("Field Guide", 144)
println(book.title) // Field Guide
println(book.pages) // 144
Java
record Book(String title, int pages) {}

// In main:
Book book = new Book("Field Guide", 144);
System.out.println(book.title());
System.out.println(book.pages());

Use new to call the constructor. Access a component with a method such as pages(). Records are final and their component fields cannot be reassigned. They generate equals, hashCode, and toString. Use equals rather than reference == to compare their data.

Build an updated value; keep the old one

Kotlin
// Reuses Book above.
val original = Book("Field Guide", 144)
val expanded = original.copy(pages = 160)
println(original.pages) // 144
println(expanded.pages) // 160
println(original == Book("Field Guide", 144))
Java
// Reuses Book above; in main:
Book original = new Book("Field Guide", 144);
Book expanded = new Book(original.title(), 160);
System.out.println(original.pages()); // 144
System.out.println(expanded.pages()); // 160
System.out.println(original.equals(
    new Book("Field Guide", 144))); // true

Java records have no generated copy method or named constructor arguments. Pass unchanged components explicitly, or write a method such as withPages that constructs a new record. Nested data follows accessor chains: a record component called book can be read with order.book().title().

Record immutability is shallow. A record may hold a reference to a mutable list, and that list can still change. Use defensive copies when needed. Generated equality compares components; an array component does not automatically gain element-by-element equality.

The traditional style: write the class explicitly

A record is convenient for a fixed group of values, but an ordinary class lets you write the fields, constructor, and methods yourself. This is an alternative to the earlier Book record: remove that declaration before trying it. Save the public class below in its own Book.java file in the same package as Demo.

Kotlin
data class Book(val title: String,
                val pages: Int)
Java
// Book.java — a separate file, not inside Demo
import java.util.Objects;

public final class Book {
    private final String title;
    private final int pages;

    public Book(String title, int pages) {
        this.title = title;
        this.pages = pages;
    }

    public String getTitle() {
        return this.title;
    }

    public int getPages() {
        return this.pages;
    }

    // Copy constructor: initialize a new book from another.
    public Book(Book other) {
        this(other.title, other.pages);
    }

    @Override
    public boolean equals(Object other) {
        if (this == other) return true;
        if (!(other instanceof Book book)) return false;
        return this.pages == book.pages
            && Objects.equals(this.title, book.title);
    }

    @Override
    public int hashCode() {
        return Objects.hash(this.title, this.pages);
    }
}

The fields store each book’s data. private keeps callers from accessing them directly, and final prevents a field from being reassigned after initialization. The constructor has the class’s name and no return type; new Book(...) calls it. In this.title = title;, the left side is this book’s field and the right side is the constructor parameter.

The public getter methods provide access to the values. Names such as getTitle() are conventional in traditional Java classes; a record generates title() instead. The getters, equals, and hashCode are instance methods, not static: they use the particular book’s fields. final on the class has a different meaning from final on a variable: it prevents another class from extending Book.

Copy a book and compare its data

Kotlin
// Reuses the Kotlin data class above.
val original = Book("Field Guide", 144)
val copied = original.copy()
println(copied.title) // Field Guide
println(copied.pages) // 144
println(original === copied) // false: different objects
println(original == copied)  // true: equal data
println(original.hashCode() == copied.hashCode()) // true
Java
// In Demo.main; uses the class in Book.java
Book original = new Book("Field Guide", 144);
Book copied = new Book(original);
System.out.println(copied.getTitle()); // Field Guide
System.out.println(copied.getPages()); // 144
System.out.println(original == copied); // false
System.out.println(original.equals(copied)); // true
System.out.println(original.hashCode()
    == copied.hashCode()); // true

The copy constructor, Book(Book other), takes an existing book and initializes a new book with the same field values. this(other.title, other.pages) delegates to the two-argument constructor. This is a shallow copy; it is sufficient here because String is immutable and int is a primitive. There are no setters, so neither book’s fields can be changed afterward. To make a book with a different page count, use new Book(original.getTitle(), 160).

equals(Object other) first accepts the same object, then rejects null or a different type using instanceof. It compares both fields: == for the primitive page count and null-safe Objects.equals for the title. @Override asks the compiler to check that the method replaces an inherited method. Because Book is final, subclasses cannot introduce additional fields that complicate this equality rule.

Equal objects must have equal hash codes. Our hashCode uses the same fields as equals, so equal books work correctly as keys in hash-based collections. Different books may still have the same hash code; compare with equals, not by comparing hash codes. An ordinary class needs these implementations (IntelliJ can generate them), while a record generates them automatically. We have not overridden toString, so this class still lacks a readable data-based string representation.

08 / Sum types & type checks

Keep a closed family; process each variant.

Sealed interfaces and records support the functional style used with Kotlin in this course.

Define alternatives and consume them

Kotlin
sealed interface Result
data class Success(val message: String) : Result
data class Failure(val reason: String) : Result

fun describe(r: Result): String = when (r) {
    is Success -> r.message
    is Failure -> "Error: " + r.reason
}
Java
sealed interface Result permits Success, Failure {}
record Success(String message) implements Result {}
record Failure(String reason) implements Result {}

static String describe(Result r) {
    return switch (r) {
        case Success s -> s.message();
        case Failure f -> "Error: " + f.reason();
    };
}

The variants hold data; a separate function handles each shape. Records are final, so they can implement this sealed interface. Keep these declarations together inside Demo. The switch covers both permitted variants and needs no default; adding a variant requires updating the cases when recompiling. These examples assume a non-null result.

Dynamic type checks bind a narrowed name

Kotlin
// Reuses Result and Success above.
val result: Result = Success("Saved")
if (result is Success) {
    println(result.message)
}
Java
// Reuses Result and Success above; in main:
Result result = new Success("Saved");
if (result instanceof Success s) {
    System.out.println(s.message());
}

instanceof checks the runtime type. When it matches, s names the value with type Success; no cast is needed. The name is available where the compiler knows the match succeeded. A null reference does not match. This corresponds to Kotlin’s is check and smart cast.

Another design: an open interface with behavior

Open interfaces are more typical in object-oriented programming: callers invoke a shared operation, and each implementation supplies its behavior. Java interfaces are open unless declared sealed; there is no open keyword. This alternative replaces the definitions above.

Dispatch the operation to the object

Kotlin
interface Result {
    fun describe(): String
}
data class Success(val message: String) : Result {
    override fun describe(): String = message
}
data class Failure(val reason: String) : Result {
    override fun describe(): String = "Error: " + reason
}
// In main:
val r: Result = Success("Saved")
println(r.describe())
Java
interface Result {
    String describe();
}
record Success(String message) implements Result {
    public String describe() { return message; }
}
record Failure(String reason) implements Result {
    public String describe() {
        return "Error: " + reason;
    }
}
// In main:
Result r = new Success("Saved");
System.out.println(r.describe());

Choose where change belongs. The sealed-data approach keeps each operation’s cases together and makes new operations straightforward. The open-interface approach lets new implementations provide the existing operations without changing callers. Callers usually need no dynamic type checks. Both designs are available in Kotlin and Java; use the one that fits the problem.

Official references: Sealed typesinstanceof patternsPattern switch

09 / Lists & operations

Separate a list interface from its implementation.

List describes ordered access. The object determines whether updates are supported.

Construct, index, and inspect

Kotlin
val scores = listOf(10, 20, 30)
println(scores[0])       // 10
println(scores.size)     // 3
println(scores.isEmpty()) // false
println(scores.contains(20)) // true
val rest = scores.drop(1) // [20, 30]
Java
// import java.util.List;
List<Integer> scores = List.of(10, 20, 30);
System.out.println(scores.get(0)); // 10
System.out.println(scores.size()); // 3
System.out.println(scores.isEmpty()); // false
System.out.println(scores.contains(20)); // true
List<Integer> rest = List.copyOf(
    scores.subList(1, scores.size()));

Java indices start at zero. List.of returns an unmodifiable list and rejects null elements. Kotlin’s read-only List interface limits operations through that reference; Java’s List exposes update methods even when its object rejects them. Invalid indices throw an exception.

Use an ArrayList when updates are intended

Kotlin
val scores = mutableListOf(10, 20)
scores.add(30)
scores[0] = 12
scores.removeAt(1)
println(scores) // [12, 30]
Java
// import java.util.ArrayList;
// import java.util.List;
List<Integer> scores = new ArrayList<>(List.of(10, 20));
scores.add(30);
scores.set(0, 12);
scores.remove(1); // remove index 1
System.out.println(scores); // [12, 30]

Watch overloaded removal. For List<Integer>, remove(1) removes an index. Use remove(Integer.valueOf(20)) to remove a value. subList is a view backed by its source; List.copyOf makes an unmodifiable snapshot of the element references. Arrays such as int[] have fixed length and use a[i] and a.length.

Official references: ListArrayList

10 / Lambdas, map, filter & fold

Build a stream pipeline, then request a result.

A Java lambda implements a functional interface: an interface with one abstract method.

Transform and select values

Kotlin
val scores = listOf(1, 2, 3, 4)
val doubled = scores.map { n -> n * 2 }
val evens = scores.filter { n -> n % 2 == 0 }
val total = scores.fold(0) { acc, n -> acc + n }
Java
// import java.util.List;
List<Integer> scores = List.of(1, 2, 3, 4);
List<Integer> doubled = scores.stream()
    .map(n -> n * 2).toList();
List<Integer> evens = scores.stream()
    .filter(n -> n % 2 == 0).toList();
int total = scores.stream().reduce(0, Integer::sum);

Stream transformations are lazy: a terminal operation such as toList or reduce triggers work. A stream is used once; create another from the list for another computation. toList() returns an unmodifiable list. Keep pipeline functions free of mutations to shared state.

Search, quantify, and name a function value

Kotlin
val names = listOf("Ari", "Bo", "Ada")
val found = names.find { it.startsWith("A") }
println(found ?: "nobody") // Ari
val any = names.any { it.length > 2 }
val all = names.all { it.isNotEmpty() }
val length: (String) -> Int = String::length
println(length("Ari")) // 3
Java
// import java.util.List;
// import java.util.function.Function;
List<String> names = List.of("Ari", "Bo", "Ada");
var found = names.stream()
    .filter(n -> n.startsWith("A")).findFirst();
System.out.println(found.orElse("nobody"));
boolean any = names.stream().anyMatch(n -> n.length() > 2);
boolean all = names.stream().allMatch(n -> !n.isEmpty());
Function<String, Integer> length = String::length;
System.out.println(length.apply("Ari")); // 3

reduce is not every fold. Stream reduction needs an associative combining operation and an identity; addition with zero fits here. For an order-dependent left fold, use an explicit accumulator loop. A lambda may capture local variables only if they are final or effectively final (never reassigned). Predicate<T> has test; Function<T,R> has apply.

Official references: StreamFunctional interfaces

11 / Mutation & shared values

References can share one mutable object.

Reassigning a variable and changing an object are different operations in both languages.

Aliases observe the same list updates

Kotlin
val first = mutableListOf(1, 2)
val alias = first
val copy = first.toMutableList()
alias.add(3)
println(first) // [1, 2, 3]
println(copy)  // [1, 2]
Java
// import java.util.ArrayList;
// import java.util.List;
final List<Integer> first = new ArrayList<>(List.of(1, 2));
List<Integer> alias = first;
List<Integer> copy = new ArrayList<>(first);
alias.add(3);
System.out.println(first); // [1, 2, 3]
System.out.println(copy);  // [1, 2]

The list constructor copies element references into a new container. It does not recursively copy mutable elements. Java passes arguments by value: a method receives a copy of a primitive value or a copy of an object reference. Mutating the referenced object can affect the caller; reassigning the parameter does not replace the caller’s variable.

Mutable object fields

Kotlin
data class Player(val name: String, var points: Int)
val player = Player("Ari", 4)
val alias = player
alias.points += 1
println(player.points) // 5
Java
static class Player {
    final String name;
    int points;
    Player(String name, int points) {
        this.name = name;
        this.points = points;
    }
}
// In main:
Player player = new Player("Ari", 4);
Player alias = player;
alias.points += 1;
System.out.println(player.points); // 5

This small class keeps the fields visible to the enclosing example. Larger object-oriented designs often make fields private and expose methods that enforce valid changes. Ordinary Java classes do not automatically get record-style equality or a useful data-based toString.

Model the intended effects. Use a record plus reconstruction when producing a new value. Use a mutable class or collection when shared state should change over time. Avoid adding or removing list elements during an enhanced for loop; build a new result or use an appropriate collection operation.

12 / Loops, ranges & input

Use enhanced for for values, counting for for indices.

Java has no built-in Kotlin range syntax. Write the initial value, continuation test, and update explicitly.

Traverse a list and count by a step

Kotlin
val scores = listOf(2, 4, 6)
var total = 0
for (score in scores) {
    total += score
}
for (i in 0 until scores.size) {
    println(scores[i])
}
for (n in 2..10 step 2) println(n)
Java
// import java.util.List;
List<Integer> scores = List.of(2, 4, 6);
int total = 0;
for (int score : scores) {
    total += score;
}
for (int i = 0; i < scores.size(); i++) {
    System.out.println(scores.get(i));
}
for (int n = 2; n <= 10; n += 2) {
    System.out.println(n);
}

Use < for an excluded upper bound and <= for an included one. A descending count can use for (int n = 5; n >= 1; n--). The loop variable belongs to the loop. break exits the nearest loop; continue skips to its next iteration.

Read lines until a sentinel or end of input

Kotlin
while (true) {
    val word = readlnOrNull() ?: break
    if (word == "quit") break
    if (word.isEmpty()) continue
    println(word.uppercase())
}
Java
// import java.util.Scanner;
// import java.util.Locale;
Scanner input = new Scanner(System.in);
while (input.hasNextLine()) {
    String word = input.nextLine();
    if (word.equals("quit")) break;
    if (word.isEmpty()) continue;
    System.out.println(word.toUpperCase(Locale.ROOT));
}

nextLine() returns a line without its line ending; hasNextLine() checks whether one is available. For numeric input, parse a complete line with Integer.parseInt(input.nextLine()). Invalid numeric text throws, so a user-facing program should handle that case. Closing this scanner also closes System.in; avoid closing shared input while other code still needs it.

Choose a form that matches the task. Use a stream to transform or summarize data, a loop for repeated effects, and a recursive method when the data itself is recursive. The course’s habits—base cases, progress, helper decomposition, and tests—still apply.
