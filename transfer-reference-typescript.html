01 / Files, running & debugging

Use WebStorm. Check types, then run.

This guide uses small console programs in JetBrains WebStorm, with Node.js 24 or newer as the runtime.

A complete starting file

Kotlin · hello.kt
fun main() {
    val name = "Gompei"
    println("Hello, $name!")
}
TypeScript · hello.ts
const name = "Gompei";
console.log(`Hello, ${name}!`);

export {};

Top-level statements run in order. No special main function is required. Backticks make an interpolated string; ${name} inserts a value. Braces group statements, // starts a comment, and this guide consistently ends statements with semicolons. An empty export {} makes a file a module, keeping its names local to that file.

  1. Create: open an empty project folder in WebStorm. Install Node.js 24+ if needed and select it as the project’s Node runtime in Settings. Add hello.ts.
  2. Configure: follow the one-time setup on the next page. In Settings, search for TypeScript, select the project’s installed TypeScript package, and enable its language service.
  3. Check: read editor diagnostics and run npx tsc --noEmit in the project terminal. Fix type errors before running.
  4. Run: in current WebStorm, right-click hello.ts and choose Run. Its Node runtime must be 24+. Output appears in the Run window. The terminal equivalent is node hello.ts.
  5. Debug: click the gutter to set a breakpoint, then choose Debug for that file. Inspect variables, Step Over a line, Step Into a call, and Resume.

Running does not check types. Node removes supported type annotations and executes the program. It does not read your type-checking configuration. WebStorm and tsc check the code separately. Types do not validate external data at runtime; sheet 8 shows an explicit check.

For a runtime failure, read the error message and find your first relevant source line in the stack trace. A successful type check does not rule out incorrect calculations, failed input, or other runtime problems.

01 / Files, running & debugging · continued

One-time project setup

In WebStorm’s Terminal, run these commands in a new project folder. The first creates package.json; the second enables modules. The final command installs the type checker and type descriptions for the runtime’s built-in APIs.

npm init -y
npm pkg set type=module
npm install --save-dev typescript @types/node@24

Create tsconfig.json at the project root with these contents:

{
  "compilerOptions": {
    "target": "ES2023",
    "module": "NodeNext",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "noEmit": true,
    "allowImportingTsExtensions": true,
    "erasableSyntaxOnly": true,
    "verbatimModuleSyntax": true,
    "types": ["node"]
  },
  "include": ["*.ts"]
}

strict enables stronger checks, including checks for missing values. noUncheckedIndexedAccess makes an array lookup potentially undefined. exactOptionalPropertyTypes distinguishes an absent property from a present property set to undefined. erasableSyntaxOnly keeps examples compatible with direct execution. noEmit makes the checker report errors without producing output files.

Share definitions explicitly

Kotlin
// In helpers.kt:
fun square(n: Int): Int = n * n

// In app.kt, same package:
fun main() {
    println(square(3)) // 9
}
TypeScript
// In helpers.ts:
export function square(n: number): number {
  return n * n;
}

// In app.ts:
import { square } from "./helpers.ts";
console.log(square(3)); // 9

With this setup, include .ts in relative imports. Use import type { Book } from "./book.ts"; for an exported type. Importing a module also executes its top-level statements on its first load, so keep demonstrations in a separate file from reusable definitions.

Snippet convention: use a separate .ts file for each independent example; add export {}; if it has no imports or exports. Copy an explicitly reused definition when needed. The configuration above checks files at the project root. No application framework or testing package is needed for this guide.

02 / Names, assignment & scope

Prefer const. Use let for reassignment.

Type annotations follow the name, as in Kotlin. Inference usually handles local initial values.

Fixed bindings and changing values

Kotlin
val limit: Int = 3
var count: Int = 0
count += 1
val label = "ready"
// limit = 4 is not allowed.
TypeScript
const limit: number = 3;
let count = 0; // inferred number
count += 1;
const label = "ready";
// limit = 4 is not allowed.
// count = "one" is a type error.

const prevents reassignment of the binding, much like val. let permits reassignment, like Kotlin var. TypeScript also has a keyword spelled var, but its older scope rules differ; prefer const and let.

Blocks and function calls have local names

Kotlin
fun nextCount(count: Int): Int {
    val next = count + 1
    return next
}
val ready = true
if (ready) {
    val message = "go"
    println(message)
}
// message is out of scope.
TypeScript
function nextCount(count: number): number {
  const next = count + 1;
  return next;
}
const ready = true;
if (ready) {
  const message = "go";
  console.log(message);
}
// message is out of scope.

Use a local name only after its declaration and initialization. Parameters belong to their function call. Unlike Kotlin parameters, TypeScript parameters can be reassigned; doing so does not reassign the caller’s variable. Choose a separate local name when it makes a calculation clearer.

A fixed binding is not an immutable object. const scores = [10, 20]; still permits scores.push(30). A read-only array type restricts updates through that reference; see sheets 9 and 11.

03 / Numbers & Booleans

Use number for everyday arithmetic.

TypeScript’s number type represents both whole and fractional values. Division does not switch behavior based on the operands’ spelling.

Arithmetic and conversion

Kotlin
val whole = 7 / 2        // 3
val decimal = 7.0 / 2    // 3.5
val remainder = -7 % 2   // -1
val parsed = "42".toInt()
val text = 42.toString()
val root = kotlin.math.sqrt(81.0)
TypeScript
const whole = Math.trunc(7 / 2); // 3
const decimal = 7 / 2;          // 3.5
const remainder = -7 % 2;       // -1
const parsed = Number("42");   // 42
const text = String(42);       // "42"
const root = Math.sqrt(81);     // 9

Math.trunc discards the fractional part toward zero; Math.floor rounds downward, which differs for negative values. ** means exponentiation: 2 ** 3 is 8. Number arithmetic uses binary floating point; compare calculated decimals with a suitable tolerance.

Compare values and combine conditions

Kotlin
val age = 20
val enrolled = true
val eligible = age >= 18 && enrolled
val needsHelp = !enrolled || age < 18
val same = age == 20
val different = age != 21
TypeScript
const age: number = 20;
const enrolled = true;
const eligible = age >= 18 && enrolled;
const needsHelp = !enrolled || age < 18;
const same = age === 20;
const different = age !== 21;

Use === and !== for equality without coercion. && and || short-circuit. Prefer Boolean conditions: if (count > 0) says more than if (count). Conditions also accept other values; zero, an empty string, null, undefined, and NaN act as false.

Kotlin ideaTypeScript choiceBehavior to remember
Int or Double calculationnumberExact integers only through ±(253 − 1).
Exact large integerbigint, e.g. 42nA separate type; do not mix with number arithmetic.
BooleanbooleanValues are true and false.

Validate converted input. Number("oops") gives NaN; Number("") gives 0. Reject blank text before conversion, then use Number.isFinite(n) for a finite number or Number.isSafeInteger(n) for a safe integer. Number.parseInt("12cats", 10) accepts a numeric prefix, so it is not a whole-input validator.

04 / Strings & missing values

Use unions to describe missing values.

TypeScript has two missing-value markers: null and undefined. Under strict checking, include the intended marker in the type.

Read, compare, and build text

Kotlin
val name = "Gompei"
val first = name[0]           // 'G'
val size = name.length       // 6
val greeting = "Hi, $name"
val same = name == "Gompei"
val part = name.substring(0, 3)
TypeScript
const name = "Gompei";
const first = name[0];        // "G"
const size = name.length;    // 6
const greeting = `Hi, ${name}`;
const same = name === "Gompei";
const part = name.slice(0, 3); // "Gom"

Strings are immutable and indexed from zero. TypeScript has no separate character type: indexing returns a string or undefined when out of bounds. slice(start, end) excludes the end. String length and indexing count UTF-16 code units, so a visible symbol may occupy more than one position.

Safe access and a default

Kotlin
fun display(nickname: String?): String {
    return nickname ?: "guest"
}
fun nameLength(nickname: String?): Int {
    return nickname?.length ?: 0
}
println(display(null)) // guest
TypeScript
function display(
  nickname: string | null
): string {
  return nickname ?? "guest";
}
function nameLength(
  nickname: string | null
): number {
  return nickname?.length ?? 0;
}
console.log(display(null)); // guest

| means “one of these types.” ?. stops on either missing marker and produces undefined; ?? supplies a fallback for either marker. It preserves "", 0, and false. Using || instead would replace those values too.

A failed array find returns undefined. You may choose null to represent explicit absence in your own data. Follow each function’s return type; use string | null | undefined only when all three cases are part of the contract.

A non-null assertion is not a check. TypeScript’s value! tells the checker to assume a value is present; it adds no runtime protection. Kotlin’s !! performs a runtime check. Prefer a branch, optional access, or a default to either assertion when absence is expected.

05 / if, when & named choices

Use branches and literal unions.

TypeScript if and switch are statements. Use a conditional expression for a simple value choice, or return from branches.

Choose one of two values

Kotlin
val age = 20
val label = if (age >= 18) "adult" else "youth"

fun sign(n: Int): String {
    if (n > 0) return "positive"
    if (n < 0) return "negative"
    return "zero"
}
TypeScript
const age = 20;
const label = age >= 18 ? "adult" : "youth";

function sign(n: number): string {
  if (n > 0) return "positive";
  if (n < 0) return "negative";
  return "zero";
}

Name a finite set of choices

Kotlin
enum class Season {
    SPRING, SUMMER, FALL, WINTER
}
fun clothing(s: Season): String = when (s) {
    Season.SUMMER -> "shorts"
    Season.WINTER -> "coat"
    Season.SPRING, Season.FALL -> "jacket"
}
val outfit = clothing(Season.FALL)
TypeScript
type Season =
  | "spring" | "summer" | "fall" | "winter";

function clothing(s: Season): string {
  switch (s) {
    case "summer": return "shorts";
    case "winter": return "coat";
    case "spring":
    case "fall": return "jacket";
  }
}
const outfit = clothing("fall");

A string literal type permits that exact spelling. The union rejects a call such as clothing("autumn") during checking. A type declaration introduces a type name, not a runtime object or constructor. Literal unions work well for a small set of named choices and with the direct-running setup on sheet 1.

A switch compares cases using strict equality. A case continues into the next case unless it returns, throws, or uses break. Here each result returns immediately; the two adjacent cases intentionally share one result.

Keep the cases complete. The explicit : string return type and strict checking catch a newly added choice that leaves a path without a return. Sheet 8 adds a never check to make exhaustive handling explicit.

06 / Function design & testing

Keep the contract and the examples.

Write a purpose, type the inputs and result, and test representative and boundary cases before adding complexity.

A complete function and executable examples

Kotlin
// Charge $2 per item; orders of at least
// 10 items receive a $3 discount.
// Requires count >= 0.
fun cost(count: Int): Int {
    return if (count >= 10) {
        count * 2 - 3
    } else {
        count * 2
    }
}
check(cost(0) == 0)
check(cost(9) == 18)
check(cost(10) == 17)
check(cost(12) == 21)
TypeScript
import assert from "node:assert/strict";

// Charge $2 per item; orders of at least
// 10 items receive a $3 discount.
// Requires a nonnegative integer count.
function cost(count: number): number {
  return count >= 10
    ? count * 2 - 3
    : count * 2;
}
assert.equal(cost(0), 0);
assert.equal(cost(9), 18);
assert.equal(cost(10), 17);
assert.equal(cost(12), 21);

Run the file in WebStorm. Passing assertions are silent; a failure throws an error showing the mismatch. assert.equal(actual, expected) checks scalar results; assert.deepEqual checks the contents of simple arrays and objects. For a calculated decimal, test a tolerance, such as assert.ok(Math.abs(actual - expected) < 1e-9).

Default arguments and functions without a result

Kotlin
fun greet(name: String = "guest"): String {
    return "Hi, $name"
}
fun announce(message: String): Unit {
    println(message)
}
announce(greet()) // Hi, guest
TypeScript
function greet(name = "guest"): string {
  return `Hi, ${name}`;
}
function announce(message: string): void {
  console.log(message);
}
announce(greet()); // Hi, guest

Use function instead of fun. A block body needs return to produce a result. Return annotations are useful contracts even when inference could supply them. void describes a function whose result callers should ignore. A default applies to an omitted argument or undefined, but not null.

Types do not express every precondition. A number parameter also accepts fractions and negative values. Check these when accepting outside input. TypeScript has no Kotlin-style named call arguments; an options object can give several parameters readable names. Keep any out of these contracts because it bypasses checking.

07 / Compound data & copies

Describe a shape. Create an object.

An interface describes an object’s fields. It does not create a constructor or generate equality and copy methods.

A record and a changed copy

Kotlin
data class Book(
    val title: String,
    val pages: Int
)
val book = Book("Trees", 80)
val revised = book.copy(pages = 96)
val title = book.title
val (name, pageCount) = book
// book.pages is still 80.
TypeScript
interface Book {
  readonly title: string;
  readonly pages: number;
}
const book: Book = {
  title: "Trees", pages: 80
};
const revised: Book = { ...book, pages: 96 };
const title = book.title;
const { title: name, pages: pageCount } = book;
// book.pages is still 80.

readonly prevents field assignment through this type. Object spread copies the fields into a new object; later fields override earlier ones. Destructuring uses property names, with title: name giving a local name. Spread is shallow: nested objects remain shared.

Compare contents deliberately

Kotlin · reuses Book
val a = Book("Trees", 80)
val b = Book("Trees", 80)
val same = a == b      // true
val identical = a === b // false
TypeScript · reuses Book
const a: Book = { title: "Trees", pages: 80 };
const b: Book = { title: "Trees", pages: 80 };
const same = a.title === b.title
  && a.pages === b.pages; // true
const identical = a === b; // false

For objects and arrays, === compares identity. Two objects with matching contents are still distinct. In tests, use assert.deepEqual(a, b) from sheet 6 for these simple records.

TypeScript uses structural typing: compatibility follows the required members. A value need not declare that it implements Book to satisfy that type. Fresh object literals receive extra checks that can catch misspelled fields. Classes are available when you need constructors and methods; plain objects suit these data descriptions.

Optional means the property may be absent. subtitle?: string permits leaving out subtitle. Reading it yields string | undefined. With this guide’s settings, explicitly storing undefined requires a type that includes it. readonly is a checking rule, not a runtime freeze, and does not recursively freeze nested data.

08 / Sum types & type checks

Tag each case of a union.

A discriminated union describes alternatives with different fields. A shared tag lets a branch identify the case and its available data.

Inventory the fields for each case

Kotlin
sealed interface Shape
data class Circle(val radius: Double): Shape
data class Rectangle(
    val width: Double,
    val height: Double
): Shape

fun area(s: Shape): Double = when (s) {
    is Circle -> Math.PI * s.radius * s.radius
    is Rectangle -> s.width * s.height
}
val disk: Shape = Circle(2.0)
val result = area(disk)
TypeScript
type Shape =
  | { readonly kind: "circle";
      readonly radius: number }
  | { readonly kind: "rectangle";
      readonly width: number;
      readonly height: number };

function area(s: Shape): number {
  switch (s.kind) {
    case "circle":
      return Math.PI * s.radius ** 2;
    case "rectangle":
      return s.width * s.height;
    default: return unreachable(s);
  }
}
function unreachable(value: never): never {
  throw new Error(`Unexpected case: ${value}`);
}
const disk: Shape = { kind: "circle", radius: 2 };
const result = area(disk);

The literal kind is the discriminant. Inside each case, the checker narrows s to the matching shape, similar to Kotlin’s smart cast. After every case is handled, no possible member remains: its type is never. Adding a variant without handling it makes the call to unreachable a type error.

Check an unknown value before using it

Kotlin
fun textLength(value: Any?): Int {
    return if (value is String) {
        value.length
    } else {
        0
    }
}
TypeScript
function textLength(value: unknown): number {
  if (typeof value === "string") {
    return value.length;
  }
  return 0;
}

unknown accepts any input but requires evidence before you use its fields or operations. typeof checks primitive categories. For object input, check that it is non-null, then validate the tag and required fields. A tag alone does not prove that the remaining fields are valid.

Type names disappear at runtime. You cannot use instanceof Shape for this union or instanceof Book for an interface. Use tags and field checks; instanceof needs a runtime constructor. Writing value as Shape merely asserts a type to the checker; it neither converts nor validates the value.

09 / Lists & operations

Use arrays for ordered collections.

A number[] is a mutable array of numbers. A readonly number[] exposes a read-only view, similar to Kotlin List<Int>.

Create, inspect, and rebuild

Kotlin
val scores: List<Int> = listOf(10, 20, 30)
val empty: List<Int> = emptyList()
val size = scores.size            // 3
val first = scores.firstOrNull()  // 10
val missing = scores.getOrNull(8) // null
val rest = scores.drop(1)         // [20, 30]
val more = scores + 40
val has20 = 20 in scores          // true
TypeScript
const scores: readonly number[] = [10, 20, 30];
const empty: readonly number[] = [];
const size = scores.length;    // 3
const first = scores[0];       // 10
const missing = scores[8];     // undefined
const rest = scores.slice(1);  // [20, 30]
const more = [...scores, 40];
const has20 = scores.includes(20); // true

Indices start at zero. With noUncheckedIndexedAccess, an ordinary array lookup has type number | undefined, even when this particular example has an element there. Check before using the result, or use a default when it fits the contract. Out-of-range reads do not throw.

Sort without changing the original

Kotlin
val values = listOf(3, 20, 1)
val sorted = values.sorted() // [1, 3, 20]
val reversed = values.reversed()
val words = listOf("red", "blue")
val text = words.joinToString(", ")
TypeScript
const values = [3, 20, 1];
const sorted = values.toSorted((a, b) => a - b);
// [1, 3, 20]; values stays [3, 20, 1].
const reversed = values.toReversed();
const words = ["red", "blue"];
const text = words.join(", ");

toSorted and toReversed return new arrays and are available in the chosen runtime. Numeric sorting needs a comparator: a negative result puts a first, zero ties, and a positive result puts b first. Without one, numbers sort by their string forms.

KotlinTypeScriptResult
xs.isEmpty()xs.length === 0Boolean empty check
xs.take(2)xs.slice(0, 2)Up to two leading elements
xs.lastOrNull()xs.at(-1)Last element, or a missing marker

Check equality and membership intentionally. Arrays use identity equality; compare contents explicitly or use deep assertions in tests. includes finds an object by identity, so use some with a field comparison to find matching data. in checks property keys, not array membership. Empty arrays act as true in conditions.

10 / Lambdas, map, filter & fold

Pass an arrow function.

Array operations keep the familiar “transform, select, combine” design. TypeScript writes the callback inside the call’s parentheses.

Transform, select, reduce, and search

Kotlin
val scores = listOf(10, 20, 30)
val doubled = scores.map { it * 2 }
// [20, 40, 60]
val high = scores.filter { it >= 20 }
// [20, 30]
val total = scores.fold(0) { acc, n ->
    acc + n
} // 60
val found = scores.find { it > 15 } // 20
val anyHigh = scores.any { it >= 20 }
val allHigh = scores.all { it >= 20 }
TypeScript
const scores = [10, 20, 30];
const doubled = scores.map(n => n * 2);
// [20, 40, 60]
const high = scores.filter(n => n >= 20);
// [20, 30]
const total = scores.reduce(
  (acc, n) => acc + n, 0
); // 60
const found = scores.find(n => n > 15); // 20
const anyHigh = scores.some(n => n >= 20);
const allHigh = scores.every(n => n >= 20);

reduce(callback, initial) puts the initial accumulator last. Always supply it for a fold: on an empty array this returns the initial value; omitting it throws. find returns the first match or undefined. some is false on an empty array; every is true.

A function that accepts a function

Kotlin
fun applyTwice(
    n: Int, f: (Int) -> Int
): Int = f(f(n))

val result = applyTwice(3) { it + 1 }
// 5
TypeScript
function applyTwice(
  n: number, f: (x: number) => number
): number {
  return f(f(n));
}
const result = applyTwice(3, x => x + 1);
// 5

An expression arrow, n => n * 2, returns its expression. A block arrow, n => { return n * 2; }, needs an explicit return. Wrap an object result in parentheses: n => ({ value: n }). Callback parameter types are usually inferred from the array or function contract.

Know what a callback receives. Array callbacks can receive the element, index, and array. Write texts.map(text => Number.parseInt(text, 10)) when you need to fix the radix; passing Number.parseInt directly accidentally uses the index as the radix. Use map for result values and for…of for a sequence of effects.

11 / Mutation & shared values

Assignment can share an object.

Reassigning a variable and changing an object are different operations. const prevents only the first.

Update numbers and array elements

Kotlin
var count = 1
count += 2
count++ // 4

val scores = mutableListOf(10, 20)
scores[0] = 11
scores.add(30)
val removed = scores.removeAt(1)
// removed: 20; scores: [11, 30]
TypeScript
let count = 1;
count += 2;
count++; // 4

const scores = [10, 20];
scores[0] = 11;
scores.push(30);
const removed = scores.splice(1, 1)[0];
// removed: 20; scores: [11, 30]

splice(start, count) removes elements in place and returns an array of removed elements; its first element may be undefined if none was removed. slice creates a copy without changing the original. pop() removes the last element, or returns undefined if empty.

Distinguish an alias from a copy

Kotlin
val original = mutableListOf(1, 2)
val alias = original
alias[0] = 99
// original is now [99, 2].

val separate = original.toMutableList()
separate[0] = 7
// original is still [99, 2].
TypeScript
const original = [1, 2];
const alias = original;
alias[0] = 99;
// original is now [99, 2].

const separate = [...original];
separate[0] = 7;
// original is still [99, 2].

A function that mutates an array or object parameter can affect the caller’s data. For a function that only reads an array, accept readonly number[]. Both mutable and read-only arrays can then be passed in, and the function cannot call mutating array methods through that parameter.

Copies and read-only views are shallow. Spreading an array copies the array, not its element objects. Mutating a shared element still affects both arrays. Likewise, a read-only array of mutable objects permits changing their fields. Choose read-only field types too when the design requires them, and rebuild nested objects when making independent changed copies.

sort and reverse mutate; toSorted and toReversed return new arrays. Avoid assigning beyond the end or using delete scores[i], which can create gaps; use array operations that preserve the intended sequence.

12 / Loops, ranges & input

Visit values with for…of.

A for…of loop visits array elements. A counter loop expresses a range; a while loop repeats while its condition holds.

Visit values and count through a range

Kotlin
val scores = listOf(10, 20, 30)
var total = 0
for (score in scores) {
    total += score
} // 60
for (i in 1..3) println(i) // 1, 2, 3
for (i in 0 until 3) println(i) // 0, 1, 2
for (i in 3 downTo 1) println(i) // 3, 2, 1
TypeScript
const scores = [10, 20, 30];
let total = 0;
for (const score of scores) {
  total += score;
} // 60
for (let i = 1; i <= 3; i++) console.log(i);
for (let i = 0; i < 3; i++) console.log(i);
for (let i = 3; i >= 1; i--) console.log(i);

A counter loop has initialization, a condition checked before each iteration, and an update afterward. Use i += 2 for a step of two. For both index and value, use for (const [i, score] of scores.entries()). Avoid for…in for array values: it visits property keys.

Read text until a sentinel

Kotlin
while (true) {
    print("Word (quit to stop): ")
    val word = readlnOrNull() ?: break
    if (word == "quit") break
    if (word.isEmpty()) continue
    println(word.uppercase())
}
TypeScript · input.ts
import { createInterface } from "node:readline";
import { stdin, stdout } from "node:process";

const lines = createInterface({
  input: stdin, output: stdout,
  terminal: false
});
console.log("Words (quit to stop):");
try {
  for await (const word of lines) {
    if (word === "quit") break;
    if (word.length === 0) continue;
    console.log(word.toUpperCase());
  }
} finally {
  lines.close();
}

Run input.ts in WebStorm’s Terminal with node input.ts for interactive input. for await…of waits for each incoming line and ends at end-of-input. The imports make this a module, where top-level await is allowed by the setup on sheet 1. finally closes the input interface even when a loop exits early or throws.

Input is text. The input loop prints one initial prompt and echoes nonempty words in uppercase. Convert numeric text deliberately using the checks on sheet 3. break exits the nearest loop; continue skips to its next iteration. An ordinary while (condition) { … } is also available when the repetition is driven by changing state.
