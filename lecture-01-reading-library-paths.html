Read a Library Path

Long import paths locate a name precisely. You can learn to read them without memorizing them.

Optional 2 minutes Vocabulary: package, path

Read from the Useful Name Backward

Consider this import:

import kotlin.math.absoluteValue

The pieces separated by dots form a path. The last piece, absoluteValue, is the name that becomes available. The earlier pieces tell Kotlin where to find it: inside math, which is part of kotlin.

Packages Organize Names

A package groups related definitions. Packages prevent unrelated libraries from colliding when they happen to use the same short name. The complete path identifies exactly which definition the file means.

import io.kotest.matchers.shouldBe

For this course, read that line as: "Use the shouldBe matcher from Kotest." You do not need to explain every piece of io.kotest.matchers. Documentation and IntelliJ can help produce the import when you need it.

Imports Keep Later Code Short

After importing a name, later code uses the short final piece. This keeps examples readable. The import carries the precise location once, near the top of the file.

Practice

  1. What usable name is introduced by import kotlin.math.absoluteValue?
  2. In io.kotest.matchers.shouldBe, which piece names the imported feature?
Check your answers

1. The usable name is absoluteValue.

2. The final piece, shouldBe, names the imported feature.
